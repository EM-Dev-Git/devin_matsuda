# トランスクリプトから議事録作成API 実装計画書

## 1. プロジェクト概要

### 目的
トランスクリプトデータを受け取り、OpenAIを使用して議事録を自動生成するAPIシステムの構築

### 主要機能
- ユーザー認証（JWT）
- トランスクリプト受信
- OpenAI連携による議事録生成
- 生成結果の返却

## 2. システム構成

### 技術スタック
- **フレームワーク**: FastAPI
- **認証**: JWT (JSON Web Token)
- **データベース**: SQLite/PostgreSQL
- **AI連携**: OpenAI API
- **ログ**: Python logging
- **環境変数管理**: python-dotenv

## 3. 詳細設計

### 3.1 認証システム

#### ユーザーテーブル設計
```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### 認証フロー
1. ユーザーログイン（POST /auth/login）
2. ユーザーID・パスワード検証
3. JWTトークン生成・返却
4. 以降のAPIリクエストでトークン検証

### 3.2 議事録生成API

#### エンドポイント設計
- **POST /transcript/generate**
- **認証**: JWT必須
- **入力**: トランスクリプトテキスト
- **出力**: 生成された議事録

#### 処理フロー
1. JWTトークン検証
2. リクエストデータバリデーション
3. OpenAI APIへリクエスト送信
4. 議事録生成
5. レスポンス返却

### 3.3 OpenAI連携

#### プロンプト設計
```
以下のトランスクリプトから議事録を作成してください。

【要求事項】
- 参加者の発言を整理
- 主要な議題と決定事項を明確化
- アクションアイテムの抽出
- 日本語で出力

【トランスクリプト】
{transcript_text}
```

## 7. API仕様

### 認証エンドポイント

#### POST /auth/login
```json
// Request
{
    "user_id": "string",
    "password": "string"
}

// Response
{
    "access_token": "string",
    "token_type": "bearer"
}
```

### 議事録生成エンドポイント

#### POST /transcript/generate
```json
// Request
{
    "transcript": "string",
    "meeting_title": "string (optional)",
    "participants": ["string"] (optional)
}

// Response
{
    "meeting_minutes": "string",
    "generated_at": "datetime",
    "status": "success"
}
```

## 8. エラーハンドリング

### HTTPステータスコード
- 200: 成功
- 400: リクエストエラー
- 401: 認証エラー

- 500: サーバーエラー
